# gtv Roadmap

> 修订于 2026-08-18。依据：design-v2.md 的规格、`docs/reference/gmaster-io/` 新入库的
> 官网存档（Branch Explorer 全界面截图、过滤栏形态、右键菜单全量项）、以及在大仓库
> （2000 提交 / 37 泳道）上的实测观察。
>
> 原则：gtv 借鉴 gmaster 的设计词汇，但不复刻它。每个里程碑只对齐"用户价值"，
> 不对齐"原作有没有这个功能"。

## 已完成的地基（2026-03 原型 → 2026-08 重写）

- 泳道传播引擎（first-parent 血缘、tip 保护墙、已合并优先）+ 9 个算法测试
- 智能压缩、时间比例 x 轴、变更量节点大小、迷你图、泳道聚焦
- 吸顶自适应精度时间轴、标签碰撞分层、边交互（高亮/跳转父/跳转子）
- 触摸板手势（双指平移、捏合缩放）、分支面板（搜索/倒序/All/None/双击 solo）
- 工程化：git 历史、基准仓库测试、mock.html 浏览器调试链

## M1 — 大仓库日常可用（最高优先级）

目标：在真实大仓库（数千提交、数百分支）上打开即用、默认视图即合理。

| # | 事项 | 背景与验收 |
|---|---|---|
| 1.1 | **异常时间间隙折叠** | 实测发现：单个时间戳异常的提交（如 2038 年）把时间比例 x 轴拉出 4 万像素空白，Fit 全景成宽扁条带。方案：超过阈值（如 90 天）的无提交间隙折叠为固定宽度 + 断轴标记（锯齿/双斜线），时间轴刻度跳过折叠段。验收：taskon-server Fit 后场景纵横比 < 4:1，刻度无误导 |
| 1.2 | **非活跃泳道收拢** | gmaster 过滤栏的 "only relevant" 就是这个。规则：已合并且 tip 超过 N 天无活动的泳道默认收拢成一条"inactive lanes"汇总行，点击展开。验收：1000+ 分支仓库打开后默认泳道数 ≤ 30 |
| 1.3 | **提交搜索定位** | Cmd/Ctrl+F 搜索 message/author/hash，回车居中到命中节点并高亮；Enter/Shift+Enter 在命中间跳转。验收：大仓库任意提交 2 秒内定位 |
| 1.4 | **规模上限治理** | revwalk 2000 上限改为显式分页/增量加载；diff stats 懒加载（详情打开才算）；渲染层继续靠 culling。验收：10k 提交仓库打开时间 < 3s，滚动不卡 |

## M2 — 过滤系统补完

目标：让"只看我现在关心的东西"成为一等能力。对齐 gmaster 过滤栏（only relevant /
remotes / 日期范围 / search）与右键过滤。

| # | 事项 | 说明 |
|---|---|---|
| 2.1 | **关联分支过滤** | 右键泳道 → "只显示相关分支"：保留该泳道的血缘链（祖先 fork 链 + 子孙 + merge 对象），其余整体隐藏。区别于现有的 Focus（仅弱化显示） |
| 2.2 | **日期范围过滤** | 顶栏下拉：last week / month / 3 months / year / all + 自定义起止。与压缩正交叠加 |
| 2.3 | **remotes 开关** | 一键隐藏 origin/* 引用（badge 与泳道同名远程项），减少一半标签噪音 |
| 2.4 | **关注集持久化** | 当前分支选择（面板里的勾选）按仓库持久化到 localStorage，重开仓库自动恢复。"日常只关注几个分支"的完整闭环 |

## M3 — 图即操作入口（含只读红线决策）

目标：从"看历史"走到"在历史里干活"。**M3 的大部分事项要求 gtv 越过只读红线，
开工前需要先做一个定位决策（见文末）。**

| # | 事项 | 说明 |
|---|---|---|
| 3.1 | 真实 checkout | switch_branch 后端已实现未接通；前端接通 + 脏工作区确认对话框 |
| 3.2 | 两提交 diff 对比 | Ctrl+点击多选两个节点 → 详情面板切换为 diff 视图（gmaster 的 "diff selected changesets"） |
| 3.3 | 节点/泳道右键全量 | 对齐存档截图的菜单：从节点建分支、merge 此分支、cherry-pick、rename/delete（依赖写操作决策） |
| 3.4 | 详情三栏联动 | 详情面板内嵌 diff 区（选中文件 → 行内 diff），而非只列文件名 |

## M4 — 视觉语言升级

目标：信息编码更丰富，向原作的图形词汇靠拢但保持 gtv 自己的深色审美。

| # | 事项 | 说明 |
|---|---|---|
| 4.1 | 双线泳道 + 空心大圆节点 | branch-explorer-full.png 确认的原作词汇：泳道为双线横杠（活跃段实线/非活跃段虚线），节点大空心圆，选中态内填。提高泳道"实体感" |
| 4.2 | 节点状态编码 | 原作节点有"下半圆填色"（语义未考据确认）。gtv 自定义为：下半圆填色 = 该提交有未推送内容（ahead），或编码 CI 状态（远期） |
| 4.3 | HEAD 家形图标 | 文字 HEAD 标签升级为图标节点（原作做法），工作区有家时的隐喻 |
| 4.4 | ahead/behind 徽标 | 本地分支相对上游的领先/落后计数，显示在泳道芯片上 |
| 4.5 | 浅色主题 | 原作是浅色；gtv 纯深色。主题变量化后补一套浅色 |

## 待决策（阻塞 M3）

1. **只读 vs 写操作**：gtv 目前对外承诺 read-only（README 写明）。越过红线带来
   确认对话框、误操作恢复、凭据管理等一整套责任。建议：M3.1/M3.2 做（低风险、高价值），
   M3.3 的破坏性操作不做或放到单独"专家模式"开关后。
2. **多仓库标签页**：原作顶栏是 repo 标签页。gtv 目前单仓库 + 记住上次。
   是否做多开，取决于实际使用场景是否出现。
3. **时间轴断轴的误导性边界**：折叠段上的提交如何标注（折叠段内其实无提交，
   但刻度必须跳过）——1.1 实现时定稿。
